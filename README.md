# بوت مهام الكلان — الإصدار 1.1.1

مشروع Node.js جديد: بوت رسمي للأوامر في سيرفر الكلان، وقارئ أحداث مستقل في أرينا. يحتوي على المهام الفردية، الحضور الصوتي، النقاط، ولوائح المتصدرين. لم يُنشر على حساب Render أو يُشغّل على حسابات ديسكورد الخاصة بك؛ ضع الإعدادات ثم نفّذ اختبار القبول أدناه.

## الجديد: تشخيص تسجيل الدخول على Render

الإصدار 1.1.1 يفصل سجلات اتصال البوت `[auth:bot]` عن القارئ `[auth:observer]` ويعرض `GATEWAY_READY` عند نجاح كل اتصال. عند الفشل يحدد اسم المتغير المعني ورمز إغلاق Gateway إذا وصل إلى المعالج. لا يطبع التوكن أو بيانات الحساب، ولا يفعّل debug الخاص بالمكتبات.

أصلحنا أخطاء النسخ الشائعة: إزالة الاقتباسين المحيطين بالقيمة وبادئة `Bot ` أو `Bearer `، مع تنبيه يذكر اسم المتغير فقط. القيم الصحيحة تبقى كما هي. المحارف الخفية والأسطر داخل التوكن أو وضع نفس التوكن للحسابين ينتج عنها خطأ إعداد واضح قبل الاتصال. لا يستنتج البرنامج صلاحية التوكن من طوله أو يفك ترميزه.

إذا استمر رفض تسجيل الدخول، شغّل الأمر التالي مرة واحدة من **Shell داخل خدمة Render نفسها** بعد نشر هذا الإصدار:

```bash
npm run diagnose
```

اترك Start Command على `npm start`؛ أمر التشخيص فحص يدوي ينتهي، وليس خدمة مستمرة. يقرأ التشخيص نفس متغيرات البيئة ونفس تنسيق القيم المستخدمين في التشغيل، ولا يحتاج MongoDB. ينفذ طلب `GET /users/@me` واحدًا لكل حساب إلى Discord، دون اتصال Gateway أو إرسال رسائل أو تعديل الحساب، ودون إعادة محاولات أو اتباع تحويلات. يطبع النتيجة ونوع الخطأ فقط.

| النتيجة | معناها والخطوة التالية |
| --- | --- |
| `REST_OK HTTP 200` | قُبل طلب REST ونوع الحساب مطابق؛ راجع نتيجة Gateway لنفس الحساب في سجل `npm start` |
| `UNAUTHORIZED HTTP 401` | Discord رفض مصادقة الطلب بالقيمة التي قرأتها عملية الفحص؛ لا تحدد النتيجة هل السبب النسخ أو إلغاء التوكن أو غيرهما |
| `ACCOUNT_TYPE_MISMATCH` | نوع الحساب في رد Discord لا يطابق المتغير المستخدم |
| `FORBIDDEN HTTP 403` أو `RATE_LIMITED HTTP 429` | منع طلب أو حد طلبات؛ يتوقف الفحص ولا يصنف التوكن غير صالح |
| `NETWORK_ERROR` أو `TIMEOUT` أو `SERVER_ERROR` | تعذر فحص المصادقة؛ ليست دليلًا على توكن غير صالح |

**قبول REST مع رفض Gateway لا يثبت وحده أن المكتبة هي السبب.** في الإصدار 1.1.0 تحول مكتبة القارئ إغلاق Gateway بالرمز `4004` إلى `TOKEN_INVALID`؛ يعرّف Discord هذا الرمز بأنه فشل مصادقة. القارئ مؤرشف، لكن لا نجزم بمشكلة توافق من هذا السجل فقط. [رموز Discord](https://docs.discord.com/developers/topics/opcodes-and-status-codes)، [مصدر مكتبة القارئ](https://github.com/aiko-chan-ai/discord.js-selfbot-v13).

على Render تكفي متغيرات Environment، ورسالة `.env not found. Continuing without it.` ليست سبب الفشل وحدها. بعد تعديل المتغيرات اختر **Save and deploy** حتى تستخدم العملية القيم الجديدة؛ خيار **Save only** لا يحدث التشغيل الحالي. إذا عرّفت نفس المتغير في الخدمة وفي Environment Group فقيمة الخدمة لها الأولوية. لا ترسل قيم التوكنات أو صورًا تظهرها عند مشاركة نتائج الفحص. [توثيق Render](https://render.com/docs/configure-environment-variables).

## لوحة setup

بعد رفع التحديث وإعادة تشغيل البوت، اكتب **`setup`** في روم كتابي عادي داخل سيرفر الكلان، أو استخدم **`/setup`**. تحتاج صلاحية إدارة السيرفر.

يرسل البوت رسالة عامة بأربعة أزرار: **التوب الشامل، توب الفويس، توب المهمات، مهامي**. نتائج الضغط تظهر للعضو وحده؛ زر «مهامي» يستخدم هوية العضو الذي ضغطه، ولا يشارك تقدمه مع غيره. التوب الشامل يجمع نقاط المهام والحضور، وتوب الفويس يحسب نقاط الحضور، وتوب المهمات يحسب مكافآت المهام. كل توب يفتح على كل الفترات أولًا، مع أزرار يومي/أسبوعي/شهري/شامل والسابق/التالي.

| ما تكتبه | النتيجة |
| --- | --- |
| `setup` | إرسال اللوحة وتجديدها كل 60 دقيقة |
| `setup 30` | إرسال اللوحة وتجديدها كل 30 دقيقة |
| `setup ٣٠` | نفس الأمر بالأرقام العربية |
| `/setup التجديد:30` | نفس الإعداد بأمر سلاش |
| `/setup الروم:#الروم التجديد:120` | وضع اللوحة في روم محدد وتجديدها كل ساعتين |

المدة من **1 إلى 1440 دقيقة**. توجد لوحة مجدولة واحدة للكلان؛ تشغيل setup مجددًا يغير مكانها/مدتها ويستبدل رسالتها السابقة. لا يعيد ضبط النقاط أو مهام الأعضاء.

يحفظ البوت ID الروم والرسالة والمدة وموعد التجديد في مجموعة `panels` داخل MongoDB. يفحص الموعد كل 30 ثانية، فيكون التجديد عند الموعد أو خلال نحو 30 ثانية بعده أثناء عمل البوت. عند إعادة التشغيل يستعيد الإعداد ويجدد مرة واحدة إذا فات الموعد، دون إرسال كل الرسائل التي فاتت أثناء التوقف. وإذا حذفت الرسالة يدويًا يستعيدها عند الفحص التالي ما دامت صلاحياته متاحة.

عند التجديد يرسل الجديدة ويحفظ مرجعها، ثم يحذف رسالته السابقة فقط. إذا فشل الإرسال تبقى اللوحة القديمة، وإذا تعذر حذف القديمة يحتفظ بمرجعها لإعادة المحاولة ويوقف إرسال لوحات إضافية حتى ينظفها. لا يحذف أمر setup الذي كتبه العضو ولا رسائل الآخرين. تعطل العملية أو الاتصال في اللحظة بين إرسال Discord وحفظ MongoDB قد يترك رسالة إضافية؛ الأزرار تبقى قابلة للاستخدام ويمكن حذف النسخة الزائدة يدويًا.

الأزرار تعالج عن طريق `interactionCreate` ومعرفات ثابتة، دون مؤقت Collector. كل ضغطة تفتح تفاعلًا جديدًا؛ لذلك لا تعتمد الاستجابة على بقاء كائن قديم في الذاكرة وتعمل بعد restart ما دام البوت متصلًا. انتهاء صلاحية توكن رد سابق لا يعني انتهاء أزرار الرسالة نفسها. التجديد الدوري ينفذ طلب إعادة نشر اللوحة، وليس بديلًا عن تشغيل البوت باستمرار. [توثيق تفاعلات Discord](https://docs.discord.com/developers/interactions/receiving-and-responding).

**مهم عند الترقية من الإصدار السابق:** فعّل **Message Content Intent** للبوت الرسمي في Developer Portal قبل إعادة التشغيل، بالإضافة إلى Server Members Intent الموجود أصلًا. أصبح هذا مطلوبًا لهذا الإصدار لقراءة الأمر الكتابي `setup` في سيرفر الكلان، حتى عند استخدام قارئ selfbot في أرينا. امنح البوت في روم اللوحة: View Channel، Read Message History، Send Messages، Embed Links. لا يحتاج Manage Messages لحذف رسائل اللوحة التي أرسلها هو. [توثيق Message Content Intent](https://docs.discord.com/developers/events/gateway#message-content-intent).

## تنبيه الربط قبل التشغيل

وضع `selfbot` يؤتمت حساب ديسكورد عاديًا تملكه وله وصول إلى أرينا. هذا مخالف لشروط ديسكورد ويمكن أن يؤدي إلى إغلاق الحساب، حتى إن اقتصر الاستخدام على القراءة. [سياسة Discord](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots).

مكتبة القارئ `discord.js-selfbot-v13@3.7.1` مؤرشفة وغير مدعومة؛ لا يوجد ضمان أن الاتصال أو جميع أحداث الصوت ستستمر بالعمل بعد تغييرات ديسكورد. [المصدر الأصلي للمكتبة](https://github.com/aiko-chan-ai/discord.js-selfbot-v13).

المشروع لا يرسل رسائل من الحساب العادي، ولا يدخله إلى رومات صوت، ولا يسجل صوتًا، ولا ينضم لسيرفرات، ولا يحتوي على استخراج توكن أو حل CAPTCHA أو تجاوز صلاحيات. لا يستطيع حساب نشاط قناة لا يملك الحساب الوصول إليها. لا نحتاج WebRTC أو DAVE لأننا لا نتصل بالصوت ولا نسجله؛ نستخدم أحداث حالة الصوت فقط.

التشغيل بهذا الوضع يتطلب أن تضبط `ACKNOWLEDGE_SELFBOT_RISK=true` بنفسك بعد فهم التنبيه. الأفضل عند توفر موافقة إدارة أرينا إضافة البوت الرسمي للسيرفرين وتغيير `OBSERVER_MODE=official`؛ نفس النقاط والمهام تبقى محفوظة.

## الموجود في النسخة

- `/مهامي` خاص بصاحب الأمر: 5 مهام، عداد وشريط تقدم لكل مهمة، مكافأة، وعدد مرات الإكمال، مع زر تحديث.
- `setup` و`/setup`: لوحة مشتركة بأزرار تعرض النتائج الخاصة لكل ضاغط، مع إعادة نشر دورية محفوظة.
- اختيار ثابت لكل عضو في كل يوم من بنك القوالب. لا يعيد زر التحديث السحب. قد تتشابه بعض المهام بين الأعضاء؛ التقدم والنقاط مستقلان دائمًا.
- يبدأ سجل اليوم عند أول نشاط مرصود أو استخدام `/مهامي`، وليس مطلوبًا فتح الأمر قبل اللعب.
- منتصف الليل بتوقيت السعودية يبدأ يوم جديد. لا نمسح نقاط الأيام السابقة؛ تتغير فترة الترتيب تلقائيًا.
- الأسبوع يبدأ الأحد افتراضيًا. الشهر شهر ميلادي، وليس آخر 30 يومًا.
- نقاط المهام منفصلة عن نقاط الحضور، ويمكن عرض ترتيب لكل نوع أو للإجمالي.
- مكافأة المهمة تلقائية عند بلوغ العدد. لا يحتاج العضو الضغط على استلام.
- حفظ MongoDB: الإعدادات، القوالب، مهام كل عضو، التقدم، نقاط اليوم، سجل إكمال المهام، والدقائق المرصودة.
- لا تحتسب رسائل البوتات أو الويبهوك أو أعضاء خارج الكلان، ولا تحتسب الرسائل الخاصة أو نشاط سيرفرات أخرى.
- أوامر الإدارة تحتاج صلاحية **Manage Server / إدارة السيرفر**، مع فحص الصلاحية داخل التنفيذ أيضًا.

## التشغيل على Render

استخدم **Background Worker مدفوعًا** للتشغيل المتواصل؛ ملف `render.yaml` مرفق بخطة `starter` ونسخة تشغيل واحدة. لا يوجد Worker مجاني، والخدمة المجانية من نوع Web Service قد تتوقف بعد الخمول، لذا لا تعتمد عليها لعدادات متواصلة. لا يتضمن المشروع طلبات إبقاء مصطنعة للخدمة. [Render Workers](https://render.com/docs/background-workers)، [قيود الخطة المجانية](https://render.com/docs/free).

1. فك الضغط وارفع **محتويات** مجلد `clan-quests-bot` إلى مستودع جديد تملكه. يكون `package.json` و`render.yaml` في جذر المستودع. لا ترفع `node_modules` أو التوكنات.
2. في Render اربط المستودع بواسطة Blueprint واقرأ تكلفة الخطة قبل الموافقة. أو أنشئ Background Worker يدويًا بهذه القيم:
   - Runtime: **Node**.
   - Node: **22.22.0**، من متغير `NODE_VERSION`.
   - Build Command: `npm ci --omit=dev`.
   - Start Command: `npm start`.
   - Instances: **1**.
3. ضع متغيرات البيئة التالية في Render، وليس داخل ملفات المستودع أو المحادثة.
4. ابدأ النشر. بعد ظهور رسالة «جاهز» استخدم `/حالة_البوت` داخل سيرفر الكلان ثم نفذ اختبار القبول.

ملف Blueprint يتبع صيغة Render لخدمات Node ومتغيرات `sync: false` التي تدخلها وقت الإعداد. [مرجع Render YAML](https://render.com/docs/blueprint-spec).

### متغيرات التشغيل

| المتغير | القيمة المطلوبة |
| --- | --- |
| `DISCORD_BOT_TOKEN` | توكن البوت الرسمي الموجود بسيرفر الكلان |
| `ARENA_USER_TOKEN` | التوكن الذي تملكه لحساب القارئ الموجود في أرينا؛ مطلوب في وضع selfbot فقط |
| `ACKNOWLEDGE_SELFBOT_RISK` | `true` فقط إذا اخترت تشغيل الحساب بعد فهم المخاطرة |
| `OBSERVER_MODE` | `selfbot` حاليًا؛ `official` إذا أضيف البوت الرسمي للسيرفرين لاحقًا |
| `MONGODB_URI` | رابط اتصال MongoDB خاص بهذا المشروع، يبدأ بـ `mongodb+srv://` أو `mongodb://` |
| `MONGODB_DB` | `clan_quests`؛ استخدم اسمًا مخصصًا لهذا المشروع |
| `CLAN_GUILD_ID` | ID سيرفر الكلان الذي تستخدم الأوامر داخله |
| `ARENA_GUILD_ID` | ID سيرفر أرينا الذي يحسب النشاط فيه |
| `GENERAL_CHANNEL_ID` | ID الشات العام في أرينا |
| `CLAN_VOICE_CHANNEL_ID` | ID روم الكلان الصوتي في أرينا |
| `CLAN_MEMBER_ROLE_ID` | ID رتبة أعضاء الكلان في **سيرفر الكلان**؛ اتركه فارغًا لحساب جميع أعضائه غير البوتات |

فعّل Developer Mode في ديسكورد للحصول على IDs. لا تضع أسماء الرومات أو روابطها بدل الأرقام. الروم في أوامر إنشاء المهام **نص ID** لأن قائمة اختيار الرومات العادية في أمر داخل الكلان لا تعرض رومات أرينا.

لـMongoDB استخدم مستخدم قاعدة بيانات مخصصًا بصلاحية قراءة وكتابة على قاعدة المشروع فقط، واسمح باتصال الاستضافة من إعدادات الشبكة لدى مزود قاعدة البيانات. لا تعطل TLS لمعالجة خطأ اتصال، ولا تستخدم توكنًا أو رابط قاعدة سبق نشره علنًا. الرابط يحفظ في Render Environment فقط.

### إعداد البوت الرسمي

أنشئ Application وبوتًا خاصًا بهذا المشروع من [Discord Developer Portal](https://discord.com/developers/applications)، وأضفه لسيرفر الكلان باستخدام `bot` و`applications.commands`. امنحه مشاهدة قناة الأوامر وإرسال الرسائل وEmbed Links؛ لا يحتاج Administrator.

فعّل **Server Members Intent** في صفحة Bot لأن المشروع يتحقق من عضوية الكلان ورتبته، وفعّل **Message Content Intent** لقراءة setup الكتابي. في وضع `official` أضف البوت إلى أرينا مع صلاحيات مشاهدة القنوات المطلوبة؛ الكود يطلب Guild Messages وGuild Voice States تلقائيًا. [توثيق Gateway Intents](https://docs.discord.com/developers/events/gateway#privileged-intents).

الحساب القارئ في وضع selfbot لا يحتاج صلاحية إدارة السيرفر، لكنه لا يحصل على صلاحيات جديدة من المشروع. الأوامر لا تسجل على هذا الحساب؛ يسجلها البوت الرسمي فقط.

## الأوامر

| الأمر | الاستخدام |
| --- | --- |
| `setup` أو `/setup` | لوحة الأزرار؛ التجديد كل 60 دقيقة افتراضيًا ويمكن تحديد مدة أخرى |
| `/مهامي` | مهام اليوم الخاصة بالعضو وتقدم كل مهمة |
| `/نقاطي` | نقاط المهام والحضور والإجمالي: يومي، أسبوعي، شهري، كلي |
| `/المتصدرين` | خيارات الفترة، نوع النقاط، والصفحة؛ 10 أعضاء بكل صفحة |
| `/ادارة_المهام اضافة` | الاسم، نوع رسائل/صوت، ID الروم، العدد، النقاط، وتكرار يومي اختياري |
| `/ادارة_المهام تعديل` | معرف القالب مع الاسم/العدد/النقاط/التكرار الجديد |
| `/ادارة_المهام قائمة` | القوالب وحالتها ومعرف كل قالب |
| `/ادارة_المهام تعطيل` أو `تفعيل` | إيقاف/إتاحة قالب للسحب القادم، مع حفظ سجل المهام السابقة |
| `/اعدادات_الحضور` | عرض إعدادات الحضور أو تغيير الروم والنقاط والدقائق والشروط |
| `/حالة_البوت` | اتصال البوت والقارئ، القنوات الأساسية، آخر رصد، الأعضاء، وفحص MongoDB |

أمثلة: اكتب اسم الأمر ثم اختر الحقول من ديسكورد؛ استبدل `ID_...` بالرقم الحقيقي:

```text
/ادارة_المهام اضافة الاسم:اكتب 100 رسالة النوع:عدد الرسائل الروم:ID_الشات العدد:100 النقاط:100 التكرار:1
/ادارة_المهام اضافة الاسم:جلسة الكلان النوع:دقائق الصوت الروم:ID_الروم العدد:30 النقاط:60 التكرار:1
/ادارة_المهام اضافة الاسم:تحدي خاص النوع:عدد الرسائل الروم:ID_الشات العدد:200 النقاط:250 عضو:@العضو
/اعدادات_الحضور النقاط:10 الدقائق:10 الحد_اليومي:500 اقل_عدد:1 تجاهل_الميوت:False تجاهل_الديفن:True
/المتصدرين الفترة:أسبوعي النوع:نقاط الحضور
```

`العدد` هو المطلوب **لكل إنجاز**. `التكرار` هو عدد المكافآت المسموح بها لنفس المهمة يوميًا: 100 رسالة، 100 نقطة، تكرار 3 يعني مكافأة عند 100 ثم 200 ثم 300 رسالة، وبحد أقصى 300 نقطة. هذه مهمة واحدة من الخمس وليست ثلاث خانات.

الحقل `عضو` يحصر القالب في عضو معين ويعطيه أولوية ضمن مهامه الخمس، ولا يجعل المهمة تظهر لبقية الأعضاء. الحد 5 قوالب خاصة نشطة للعضو.

## القوالب الأولية والتجديد

عند تشغيل قاعدة جديدة تنشأ 8 قوالب قابلة للتعديل:

| النوع | العدد المطلوب | النقاط |
| --- | --- | --- |
| رسائل بالشات العام | 25 / 50 / 100 / 150 / 200 | 25 / 50 / 100 / 150 / 200، كل عدد قالب مستقل |
| دقائق بروم الكلان | 10 / 20 / 30 | 20 / 40 / 60، كل مدة قالب مستقل |

يسحب كل عضو 5 قوالب. الرسالة أو الدقيقة الواحدة تتقدم بها **كل مهامه المطابقة للروم**؛ هذا مقصود. إذا عنده مهمتا 50 و100 رسالة، يصل تقدم الاثنتين معًا. لا توجد بعد مهام غير الرسائل والصوت؛ إضافة نوع إنجاز جديد لاحقًا تحتاج معالجًا برمجيًا جديدًا، أما إضافة أهداف ونقاط وقنوات لهذين النوعين فمن الأوامر.

تعديل قالب لا يغير مهمة سبق سحبها اليوم، حتى لا يتغير هدف العضو أو مكافأته أثناء الإنجاز. يؤثر على السحب القادم؛ الأعضاء الذين لم يبدأ سجلهم اليوم قد يسحبون الإعداد الجديد في اليوم نفسه. تعطيل قالب لا يلغي نسخة اليوم الموجودة عند العضو. لا يسمح أمر التعطيل بالنزول عن 5 قوالب عامة نشطة.

التجديد لا يحتاج مهمة مجدولة ولا حذف بيانات: مفتاح السجل هو الكلان + العضو + التاريخ السعودي. عند منتصف الليل تستخدم الأوامر والأحداث سجل التاريخ الجديد. لوحة `/مهامي` القديمة لا تعدّل نفسها تلقائيًا؛ اضغط تحديث. قد يتكرر قالب من الأمس ضمن الاختيار العشوائي.

## الحضور والرسائل: قواعد الاحتساب

الحضور الافتراضي: **10 نقاط لكل 10 دقائق، حتى 500 نقطة يوميًا**. يحتسب الوجود منفردًا، ويحتسب الميوت، ولا يحتسب الديفن. تستطيع تغييرها بواسطة `/اعدادات_الحضور`. شرط أقل عدد يعتمد على عدد البشر في الروم، ويستبعد البوتات؛ الحاضر الآخر ليس مطلوبًا أن يكون من الكلان. نقاط المكافأة لا تعطى إلا لعضو كلان مؤهل.

شروط أقل عدد/الميوت/الديفن نفسها تنطبق على المهام الصوتية. غرف AFK وحالات Stage المقموعة لا تحتسب. إيقاف `مفعل` يوقف نقاط الحضور الإضافية فقط، ولا يوقف مهام الصوت.

يؤخذ الوقت المرصود كل 15 ثانية وعند انتقال الصوت. أجزاء الدقيقة تحفظ، وعند منتصف الليل يبدأ تقدم اليوم وفترة الحضور من جديد. عند تغيير إعداد الحضور تبقى النقاط والدقائق السابقة، وتبدأ الفترة الجزئية وفق الإعداد الجديد دون إعادة تسعير القديم. إذا خُفض الحد تحت النقاط المكتسبة لا تُسحب النقاط السابقة.

لا نحتسب وقت انقطاع القارئ/قاعدة البيانات/البوت أو نوم الاستضافة، ولا نفترض أن العضو ظل في الروم أثناء التوقف. آخر فترة غير محفوظة عند توقف قسري قد تضيع، وأحداث فاتت أثناء الانقطاع لا يمكن ضمان استعادتها. جلسة ظاهرة بعد إعادة التشغيل تبدأ مراقبتها من وقت عودة الاتصال؛ ليست دليلًا على حضور وقت الانقطاع.

فلتر الرسائل الافتراضي: رسالة مؤهلة كل 10 ثوانٍ للعضو، 3 أحرف على الأقل، وفيها حرف أو رقم. يتجاهل الرموز فقط، وتكرار النص بعد توحيد المسافات والحروف، وتكرار ID الرسالة. يحتفظ ببصمات آخر 100 نص مؤهل ضمن 10 دقائق لمنع التناوب بين نفس الرسائل. لا تحتسب الرسائل القديمة عند تشغيل البوت، ولا الزيادات من تعديل رسالة، ولا تسحب النقاط تلقائيًا عند حذف رسالة سبق احتسابها.

متغيرا `MESSAGE_COOLDOWN_SECONDS` و`MIN_MESSAGE_LENGTH` يغيران الفلتر بعد إعادة النشر. `WEEK_START_DAY` يغير بداية الأسبوع: 0 الأحد، 1 الاثنين، حتى 6 السبت. لا تغير البداية أثناء منافسة قائمة دون إبلاغ الأعضاء لأن حدود الترتيب ستتغير.

## الحفظ والخصوصية

المشروع لا يحفظ محتوى الرسائل أو الصوت. يحفظ IDs والعدادات والتوقيت وبصمات نصوص للفلترة. القوالب في `templates`، إعداد الحضور في `settings`، وسجل العضو اليومي في `days`. قفل `leases` يمنع نسختين من العمل بالتوازي لنفس الكلان.

المهمة ونقاطها تحدثان معًا داخل وثيقة يومية واحدة باستخدام رقم إصدار ومقارنة قبل الحفظ، مع إعادة المحاولة عند التزامن. هذا يستفيد من ذرية الكتابة على الوثيقة الواحدة في MongoDB ولا يحتاج معاملات متعددة الوثائق. [توثيق MongoDB](https://www.mongodb.com/docs/manual/core/write-operations-atomicity/).

الإعدادات المحفوظة لا تعاد تهيئتها عند restart. متغيرات الحضور في البيئة تستخدم كقيم أولية فقط عند إنشاء قاعدة المشروع؛ بعد ذلك عدّلها من الأمر. لا تمسح `days` لتصفير اليوم؛ حذفها يفقد سجل الترتيب. نقاط عضو خرج من الكلان تبقى في السجل التاريخي، لكن لا يكسب نقاطًا جديدة ما دام غير مؤهل. خذ نسخًا احتياطية دورية لدى مزود MongoDB.

لأعضاء الكلان حق معرفة ما يُحتسب؛ أعلن لهم أن النظام يحتفظ بعدادات نشاطهم في القنوات المحددة. لا تمنح توكن القارئ أو رابط قاعدة البيانات لأشخاص آخرين.

## اختبار القبول بعد النشر

1. تأكد أن `/حالة_البوت` يبين القارئ والأعضاء والقنوات المطلوبة، وأن الأوامر تظهر في **سيرفر الكلان**.
2. افتح `/مهامي` لعضوين: تحقق من 5 مهام ومن أن نشاط عضو لا يغير تقدم الآخر.
3. أرسل من عضو كلان رسالة مؤهلة في الشات المحدد بأرينا، ثم حدّث التقدم. جرّب نفس النص ورسالة سريعة؛ ينبغي ألا تزيدا العداد.
4. جرّب رسالة في قناة أخرى/من عضو خارج الكلان؛ لا تحتسب.
5. جرّب دخول عضو وخروجه من روم الصوت **مع عدم وجود الحساب القارئ في الروم نفسه**. تأكد أن التقدم يتوقف بعد خروجه أو انتقاله. هذه خطوة ضرورية للتحقق من وصول أحداث الصوت لحسابك؛ اللون الأخضر وحده لا يكفي.
6. اختبر إعداد حضور قصير، ثم أعد الإعداد المطلوب بعد التجربة. تغيير الإعداد لا يخصم النقاط التي اكتسبت في الاختبار.
7. أعد تشغيل الخدمة: النقاط والمهام تبقى، ووقت التوقف لا يحتسب حضورًا.
8. بعد أول منتصف ليل سعودي، تحقق من تصفير مهام اليوم مع بقاء النقاط في الترتيب الأسبوعي والشهري بحسب الفترة.
9. اكتب `setup 1` واختبر الأزرار من عضوين: مهامي ونتائج التوب تظهر لصاحب الضغطة، واللوحة العامة تبقى كما هي. تحقق من فترة الترتيب والتنقل بين الصفحات.
10. بعد دقيقة إلى دقيقة ونصف تأكد من وجود لوحة جديدة واختفاء السابقة، ثم أعد المدة المطلوبة مثل `setup 60`. أعد تشغيل البوت وتأكد أن الجدول والأزرار يعملان بلا إعادة setup.

## الاختبارات البرمجية وحالة التحقق

```bash
npm ci
npm test
npm run check
npm run test:db
```

`npm test` يغطي المنطق والأوامر وتوافق تهيئة المكتبتين ومحاكاة تحديث الوثيقة بالتزامن، بدون اتصال بحسابات ديسكورد. `test:db` اختبار إضافي يبدأ MongoDB محليًا مؤقتًا باستخدام اعتماد تطوير؛ لا يستخدم `MONGODB_URI` الحقيقي ولا يتصل بقاعدة إنتاج. يحتاج نظامًا يسمح بتشغيل MongoDB وتنزيل ملفه الثنائي.

نجحت الاختبارات المحلية للمنطق والأوامر والفحص النحوي. **لم يكتمل اختبار خادم MongoDB الفعلي هنا**: بيئة التنفيذ أعادت `open: Operation not permitted` عند بدء الخادم المحلي، لذلك لم نحاول تجاوز القيد. كما لم نختبر تسجيل دخول حسابك أو تسجيل الأوامر على سيرفرك أو النشر على Render لعدم وجود الإعدادات الخاصة. تفاصيل نتيجة التحقق في `VERIFICATION.md`.

## أعطال شائعة

| العرض | ما تتحقق منه |
| --- | --- |
| Disallowed intents | فعّل Server Members Intent وMessage Content Intent للبوت الرسمي في جميع الأوضاع |
| لا يستجيب لـ setup الكتابي | فعّل Message Content Intent، وتأكد أنك تكتبه وحده أو مع عدد الدقائق في سيرفر الكلان وبصلاحية إدارة السيرفر |
| لا تتجدد اللوحة | تحقق من تشغيل البوت واتصال MongoDB وصلاحيات قراءة وإرسال الرسائل في الروم؛ إعادة النشر قد تتأخر حتى 30 ثانية عن الموعد |
| لا يوجد تقدم للرسائل | تطابق IDs، رتبة عضو الكلان، القناة ضمن مهام العضو، فلتر الوقت والتكرار، وظهور القارئ متصلًا |
| لا يوجد تقدم للصوت | عضوية الكلان، الديفن/الميوت/عدد البشر، صلاحية مشاهدة الروم، ووصول أحداث الدخول والخروج فعليًا للقارئ |
| لا تظهر مهام جديدة بعد تعديل قالب | مهام اليوم المسحوبة ثابتة؛ انتظر اليوم التالي |
| MongoParseError | الرابط يبدأ بالمخطط الصحيح، وليس اسم قاعدة أو رابط صفحة Atlas |
| MongoServerSelectionError | إعدادات الشبكة لدى مزود قاعدة البيانات، صحة المستخدم وكلمته، والرابط وTLS |
| نسخة أخرى تعمل | يوجد تشغيل محلي أو نشر قديم بنفس الكلان والقاعدة؛ أوقف النسخة القديمة واترك القفل يتحرر |
| توقف فجأة/الحساب خرج | افحص حالة الحساب ومكتبة selfbot المؤرشفة؛ لا توجد محاولات تجاوز حظر أو تحقق في المشروع |
| طلب Render منفذًا | أنشأت Web Service بدل Worker. استخدم Background Worker كما في الملف المرفق |

للتشغيل المحلي فقط يمكنك نسخ `.env.example` إلى `.env` يدويًا وملء القيم، ثم `npm start`. لا ترفع الملف المملوء إلى المستودع. للتشغيل في Render تكفي Environment Variables.
